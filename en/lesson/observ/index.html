Observability and debugging

Seeing what the app is doing: logs, events, metrics, commands inside the pod, and API changes.

12 minIntermediate10 steps

You will learn

  • Read logs, including specific containers
  • Know where logs live and how to centralise them
  • Use events and kubectl top
  • Debug with exec, port-forward and debug
  • Format output with jsonpath and custom-columns
  • Deal with deprecated APIs

Step by step

Step 1 · Contextkubectl logs: what the app said

Everything the container writes to standard output (stdout and stderr) becomes a log. kubectl logs api-7d9 shows it; -f follows live; --tail=50 takes just the end.

For many replicas: kubectl logs -l app=api or kubectl logs deploy/api (picks a pod from the Deployment).

Key idea: Apps in containers should write to stdout, not to a file. That way Kubernetes captures it with no extra setup.

kubectl logs -f deploy/api

Step 2 · ConceptPods with more than one container

If the pod has more than one container, kubectl logs asks you to pick: -c app or -c log. --all-containers=true joins them all.

Init containers have logs too. If the pod is stuck in Init, read the init container’s log by name.

kubectl logs api-7d9 -c log-shipper

Step 3 · ConceptWhere logs live

On the node, the runtime writes logs to /var/log/pods and the kubelet rotates them. When the pod is deleted, those logs go with it.

To keep and search them, an agent like Fluent Bit runs on every node (a DaemonSet), reads that folder and ships it to a central system like Loki or Elasticsearch.

Good to know: kubectl logs only shows what’s still on the node. Long history depends on the central system.

Step 4 · ConceptEvents: the cluster’s diary

Kubernetes records events: Scheduled, Pulling, Pulled, Started, BackOff, FailedScheduling. They show at the end of describe and in kubectl get events.

Events expire after about an hour. Sort them by time with --sort-by=.lastTimestamp and filter with --field-selector.

Watch out: Events are the first clue when the log is empty, as with ImagePullBackOff and Pending.

kubectl get events -A --sort-by=.lastTimestamp

Step 5 · ConceptMetrics: kubectl top

metrics-server collects CPU and memory from each kubelet. With it installed, kubectl top nodes and kubectl top pods show current usage.

Use --sort-by=cpu or memory to find the heaviest pod, and --containers to see per container. The HPA uses these same metrics.

Good to know: Without metrics-server, kubectl top answers “Metrics API not available”.

kubectl top pods -A --sort-by=memory

Step 6 · ConceptGetting into the pod and opening a tunnel

kubectl exec -it api-7d9 -- sh opens a terminal inside the container. Good for checking files, variables and testing connections.

kubectl port-forward svc/api 8080:80 creates a tunnel from your computer to the Service. You reach localhost:8080 without exposing anything outside.

kubectl port-forward svc/api 8080:80

Step 7 · Conceptkubectl debug: when the container has no shell

Minimal images (distroless) have no sh and no tools. exec doesn’t help.

kubectl debug adds an ephemeral container to the pod, with any image you like (busybox, netshoot), sharing the target container’s processes and network with --target.

Good to know: kubectl debug node/node-1 -it --image=busybox opens a pod with access to the node’s system, under /host.

kubectl debug -it api-7d9 --image=busybox --target=api

Step 8 · ConceptOutput made to measure

-o wide shows IP and node; -o yaml shows the whole object. -o jsonpath='{.items[*].metadata.name}' pulls out just what you want.

-o custom-columns builds a table with the columns you pick, and --sort-by sorts by any field.

Key idea: The exam often asks “save list X to file Y”. jsonpath and custom-columns get it done fast.

kubectl get pods -o custom-columns=NAME:.metadata.name,NODE:.spec.nodeName

Step 9 · Trade-offTrade-off: APIs that get retired

Every object has an apiVersion. Beta versions get replaced and, after a warning period, removed. Ingress in extensions/v1beta1 stopped existing in 1.22; today it’s networking.k8s.io/v1.

Old manifests stop working when the cluster is upgraded. kubectl api-resources and api-versions show what the cluster accepts.

Watch out: Before an upgrade, look for removed apiVersions in your manifests and charts. kubectl warns when you use deprecated APIs.

kubectl api-resources | grep -i ingress
