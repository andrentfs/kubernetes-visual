Imagens de container

Como uma imagem é montada em camadas, construída, publicada e mantida pequena e segura.

10 minIniciante9 passos

Você vai aprender

  • Fazer builds multi-stage
  • Usar tags com responsabilidade

Passo a passo

Passo 1 · ContextoUma imagem é uma pilha de camadas

Uma imagem não é um arquivo único: é uma pilha de camadas, uma em cima da outra. Cada instrução do Dockerfile cria uma camada.

A primeira é a base (como node:22, que já traz o Node.js); depois vêm seus arquivos e comandos.

Passo 2 · ConceitoO Dockerfile, linha por linha

FROM escolhe a imagem base. WORKDIR define a pasta de trabalho. COPY traz arquivos do seu computador. RUN executa um comando durante o build, como instalar dependências.

CMD (ou ENTRYPOINT) diz o que rodar quando o container ligar. docker build -t loja/api:1.0 . junta tudo numa imagem com nome e tag.

Bom saber: Ferramentas como podman e buildah usam o mesmo Dockerfile, sem precisar do Docker.

docker build -t loja/api:1.0 .

Passo 3 · ConceitoCache: só refaz o que mudou

Ao reconstruir, as camadas que não mudaram vêm do cache. Se só o código mudou, só a última camada (COPY . .) é refeita: o build leva segundos.

Por isso a ordem importa: o que muda pouco (dependências) vai em cima; o que muda sempre (código), por último.

Passo 4 · ProblemaOrdem errada, build lento

Se COPY . . vier antes do RUN npm ci, qualquer mudança de código invalida o cache dali para baixo. As dependências são baixadas de novo a cada build.

Copie primeiro só o package.json, instale, e depois copie o resto.

Atenção: Uma camada alterada invalida todas as que vêm depois dela.

Passo 5 · SoluçãoPublicar no registry

docker push envia a imagem para um registry (Docker Hub, GHCR, ECR, Harbor). Os nodes do cluster baixam de lá quando um pod precisa.

O nome completo inclui o registry: registry.loja.com/api:1.0. Sem o endereço, o padrão é o Docker Hub.

docker push registry.loja.com/api:1.0

Passo 6 · ConceitoMulti-stage: construir grande, entregar pequeno

Compilar precisa de ferramentas pesadas; rodar, não. Um Dockerfile multi-stage tem vários FROM: o primeiro estágio compila, o último copia só o resultado (COPY --from=build).

A imagem final fica com dezenas de MB em vez de centenas: baixa mais rápido e tem menos coisas para um invasor usar.

Passo 7 · Trade-offTrade-off: o perigo do latest

latest é só um nome, não quer dizer “a mais nova”, e pode apontar para coisas diferentes em momentos diferentes. Dois nodes podem rodar versões diferentes com a mesma tag.

Use tags com versão (api:1.4.2) ou, para garantir, o digest (api@sha256:…), que identifica o conteúdo exato.

Atenção: imagePullPolicy Always baixa toda vez; IfNotPresent usa o que já estiver no node. Com latest, o padrão é Always.

Passo 8 · ConceitoImagens mais seguras

Comece de uma base mínima (alpine, distroless). Adicione USER com um usuário sem privilégios, para o container não rodar como root.

Escaneie a imagem com ferramentas como Trivy antes de publicar, e reconstrua quando a base receber correções.
